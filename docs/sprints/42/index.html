Adversarial Examples: Small Changes, Wrong Answers

Random noise barely moves a model. A change of the same size, chosen against it, breaks it.

In short. What an adversarial example is, why noise and a chosen change differ, how many small pushes add up across many pixels, and how attacks travel between models.

Sprint

Fig. 1 in words

One budget, two changes · 540 real test digits (UCI) · same data as code 05

  1. 1 One digit, three versions

    • original · net: 3 · >99.9%
    • noise ±2 · net: 3 · >99.9%

  3. 3 Why: signs add up

    • linear model, weights of 8 minus 3: red + · blue −
    • push ε · sign(w): no pixel works against it
    • size of the push, same ±ε: random signs ≈ ε·√Σw² · chosen 5.43× · ceiling √64 = 8×
    • chosen = ε·Σ|w| · mean of 45 digit pairs

  4. 4 Defences, tested again

    • net · no defence: 21.5%
    • linear · no defence: 46.7%
    • linear, trained on old attacks · replayed: 88.5%
    • same linear model · fresh attack: 15.9%
    • net, adversarial training · fresh attack: 74.3%
    • accuracy under a ±2 change · adversarial training, clean: 97.2%

Analyst notes

  1. 1Pick Digit 29 is a 3. Noise of ±2 leaves it a 3; the chosen ±2 makes it an 8 at 99%.
  2. 2Size At ±2 grey levels, noise keeps the net at 95.4%; the chosen change leaves 21.5%.
  3. 3Why In the linear model each pixel follows the sign of its weight, so pushes add: 5.43× random signs.
  4. 4Retest Linear model trained on old attacks: 88.5% when they are replayed · 15.9% against a fresh one.

01 A Chosen Change Definition

  • Evasion (NIST AI 100-2): a small, deliberate change to an input that causes an error
  • Named adversarial examples by Szegedy et al. (2014); Biggio et al. (2013) built them with gradients too
  • Budget here: ±2 steps per pixel on the 0–16 grey scale

Older than the name: in 2004 Dalvi et al. showed spam filters can be tricked by a few chosen changes.

02 Noise vs. Attack Claim fails

  • Claim: “if random noise does not hurt a model, small changes cannot”
  • ±2 levels on 540 test digits: noise keeps the net at 95.4%, a chosen change of the same size leaves 21.5%
  • Linear model: 95.4% against 46.7%

Fawzi et al. (2016): random noise must be about √d times the smallest attack (ℓ₂), if the boundary is gently curved.

03 Many Small Pushes Why

  • A linear score moves by ε·Σ|wᵢ| when every pixel follows the sign of its weight (Goodfellow et al. 2015)
  • Random signs mostly cancel: about ε·√Σwᵢ²
  • Linear model's weights: the chosen push is 5.43× the random one, mean of 45 digit pairs (ceiling √64 = 8)

Goodfellow et al., listing Szegedy et al.'s findings: “shallow softmax regression models are also vulnerable”.

04 Attacks Travel Transfer

  • Changes computed on the linear model alone take the net from 97.8% to 35.7%
  • Szegedy et al.: the same perturbed input also fooled a net trained on another subset of the data
  • Papernot et al. (2016): 96.19% and 88.94% misclassified by two commercial services after 800 queries

Hiding the weights does not hide the weakness.

05 Try It Yourself PY 3.13.18 · NUMPY 2.5.3 · SKLEARN 1.9.1

sprint42_adversarial_examples_small_changes_wrong_answers.py

import numpy as np
from sklearn.datasets import load_digits
from sklearn.linear_model import LogisticRegression as LR
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier as MLP
X, y = load_digits(return_X_y=True); X = X / 16  # grey 0..16 -> 0..1
Xa, Xt, ya, yt = train_test_split(X, y, test_size=.3, stratify=y,
                                  random_state=42)
lin = LR(max_iter=5000).fit(Xa, ya)                    # linear model
net = MLP((64,), max_iter=3000, random_state=42).fit(Xa, ya)
def grad(m, X, y):                      # d loss / d pixel
    P = m.predict_proba(X); P[np.arange(len(y)), y] -= 1
    if hasattr(m, "coef_"): return P @ m.coef_
    (W1, W2), b1 = m.coefs_, m.intercepts_[0]
    return (P @ W2.T * (X @ W1 + b1 > 0)) @ W1.T
def attack(m, X, y, e, steps=10):       # sign steps kept within ±e
    A = X.copy()
    for _ in range(steps):
        A = A + e / 4 * np.sign(grad(m, A, y))
        A = np.clip(np.clip(A, X - e, X + e), 0, 1)
    return A
pct = lambda m, X: f"{100 * m.score(X, yt):.1f}%"
noise = np.random.default_rng(42).choice([-1, 1], Xt.shape)
print(len(yt), "test digits | clean: linear", pct(lin, Xt), "net",
      pct(net, Xt))
for lv in range(1, 5):                  # change of lv grey levels
    e = lv / 16; R = np.clip(Xt + e * noise, 0, 1)
    print(f"±{lv} linear: noise {pct(lin, R)} attack",
          pct(lin, attack(lin, Xt, yt, e)), "| net: noise",
          pct(net, R), "attack", pct(net, attack(net, Xt, yt, e)))
e = 2 / 16                              # the change on Fig. 1
W = lin.coef_; r = [abs(W[i] - W[j]).sum() / np.linalg.norm(
    W[i] - W[j]) for i in range(10) for j in range(i)]
print(f"chosen / random push: {np.mean(r):.2f} (ceiling sqrt(64) = 8)")
A = attack(lin, Xt, yt, e)              # made on the linear model
print("made on linear, given to net:", pct(net, Xt), "->", pct(net, A))
rob = LR(max_iter=5000).fit(np.vstack([Xa, attack(lin, Xa, ya, e)]),
                            np.r_[ya, ya])     # trained on old attacks
print("defence | old attack:", pct(rob, A), "fresh attack:",
      pct(rob, attack(rob, Xt, yt, e)))
adv = MLP((64,), random_state=42)
adv.partial_fit(Xa, ya, classes=np.arange(10))
for _ in range(200):                    # adversarial training
    adv.partial_fit(np.vstack([Xa, attack(adv, Xa, ya, e, 5)]),
                    np.r_[ya, ya])
print("adversarial training | clean:", pct(adv, Xt), "attack:",
      pct(adv, attack(adv, Xt, yt, e)), "50 steps:",
      pct(adv, attack(adv, Xt, yt, e, 50)))

06 General Notes Practice

  • Linear model trained on old attacks: 88.5% replayed · 15.9% fresh · undefended 46.7%
  • Athalye et al. (2018): 7 of 9 non-certified ICLR 2018 defences relied on obfuscated gradients · 6 fully broken · 1 partly
  • Adversarial training of the net (Madry et al. 2018): 74.3% · 73.9% at 50 steps

Bridge: test a defence with an attack that knows it (Carlini et al. 2019).
