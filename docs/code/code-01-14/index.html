One source, two tool versions · Sprint 25’s wheel, built twice with each · SHA-256 as an 8 × 8 square

  1. 1 Sprint 25’s wheel, built twice with each

    • hatchling 1.32.4 · build 1 · 06334646fb0ae368… · 917 B
    • = hatchling 1.32.4 · build 2 · 06334646fb0ae368… · 917 B
    • NOT THE SAME
    • hatchling 1.33.0 · build 1 · 5620af12e1711f04… · 913 B
    • = hatchling 1.33.0 · build 2 · 5620af12e1711f04… · 913 B
    • One cell per hex digit of the SHA-256 (0 dark → f bright). Same version, same square, to the bit. Hatchling 1.32.4 was current when Sprint 25 was posted (3 Oct 2026); 1.33.0 came out on 28 Oct 2026.

  2. 2 Inside the wheel · toytok-0.1.0.dist-info/WHEEL

    • Wheel-Version: 1.0
    • - Generator: hatchling 1.32.4
    • + Generator: hatchling 1.33.0
    • Root-Is-Purelib: true
    • Tag: py3-none-any
    • One line differs. RECORD changes with it, because it lists the SHA-256 of WHEEL. Compressed, WHEEL loses 1 byte and RECORD 3.
    • Check: (86 - 85) + (204 - 201) = 4 = 917 - 913

01 · Popular claim, tested Holds only with the same tool versions

“Same code, same result.”

Sprint 25’s code, built on 13 Nov 2026 without its pin, gives a different wheel: 913 B, not the 917 B on the image. Two builds with one version agree to the bit.

Reproducible Builds counts the build environment as an input; hatchling builds reproducibly by default.

02 · Bridge · The pin has a version too

Since pip 26.2, PIP_CONSTRAINT no longer reaches pip’s own build environments. With pip 26.3 and one pin file, pip wheel built with hatchling 1.33.0 under PIP_CONSTRAINT and 1.32.4 under PIP_BUILD_CONSTRAINT; python -m build (1.6.1) still applied PIP_CONSTRAINT.

NumPy too: NEP 19 lets Generator streams change between releases, so every folder using NumPy pins it.

Pinning is not proof. Read the Generator line of what you built.
